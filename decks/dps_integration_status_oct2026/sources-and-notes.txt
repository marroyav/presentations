VD detector protection — speaker notes
I&I presentation, 28 October 2026

The argument
We begin with responsibilities and connections, then review the facility systems.
The consortium interlock matrix introduces our method before the detector:
check the proposed interlocks, trace each physical/control path, then identify
hardware coverage and additions. The PLC logic explains how those functions
are executed. Each detector system then gets its own description and example.

1. Definitions and responsibilities
DPS arbitrates protection. SC operates, monitors and coordinates requests; it
owns the logs. DAQ consumes availability and activity. Equipment owners define
limits, action time and scope. BMS and cryogenics retain control of their own
systems. Local protection remains in place. During a phase without DPS, agree
who protects the equipment; Manuel's starting proposal is its owning consortium.

2. Facility information reaches DPS through SC
FFDG BMS, SDSTA BMS and cryogenics each feed SC. SC and DPS communicate over
OPC UA. Detector services communicate through SC/OPC UA; DPS uses SNMP for
PDUs/WIENER supplies and EtherCAT for remote I/O. Wired supply inhibits are
connected through that I/O. The SDSTA route is under investigation. The central
DPS PLC in the CUC is a proposal. VD is the scope; HD may extend it or use another PLC.

3. FFDG DUNE FD BMS
ISD proposes a Metasys API in Batavia for the interface to DUNE FD SC. Manuel
reports the API/SBN building exercise and OPC UA server for experiments there.
The live-data licence is missing. Local tests demonstrate historical extraction
and OPC UA replay, not a continuous qualified live feed. The native BMS field
network is documented as BACnet; this is separate from the API integration.
The vertical map locates DUNE building services within the wider SURF service
infrastructure. Its 4850 HVAC/chilled-water and 4910 sump examples come from
the BMS drawing/register. Cryogenic process control is outside the BMS scope shown.

4. SDSTA BMS

5. Cryogenics
Manuel clarifies that cryogenics lives in the CUC. Its internally divided
controls appear as one system to DUNE. The architecture and historical design
review describe process and safety controls. They do not constitute an agreed
DUNE run-permit contract. Define the readiness states and valid source signals
for each phase. Existing requirements identify low LAr level, relief-valve
opening and specified boiling risks as HV/bias inputs. Some relevant levels
originate in detector instrumentation; name the actual sensor/readout path.

6. Start with the interlocks proposed by each consortium
This is the transition into the detector review. The matrix contains the
current ICD requirements and consortium proposals. Read each condition and
proposed action, identify the protected loads, and trace source -> input ->
decision -> actuator -> feedback. Include detection through completed shutdown.
Use the existing rack lists, drawings, parts and power workbooks. Each reviewed
rule contributes hardware already covered, additions with quantities, wiring/
software tasks, and open choices that affect hardware. Several rules may use
one physical endpoint; count it once. A missing description does not itself
prove missing equipment. Keep requirement conflicts visible for owner agreement.

7. DPS brain logic
The commercial PLC extends the BDE approach. It receives conditions, input
validity and SC requests; evaluates per-load permits; applies the outputs;
and checks the resulting equipment state. A permitted enable requires a valid
request, required conditions and no blocking trip. Trips retain cause/state.
SC records cause, decision and readback. Reset and re-enable are separate.
Specify stale-data, bus-loss and power-loss behavior per function rather than
assuming a universal response. Existing local equipment interlocks remain active.
These are the proposed logic principles, not a claim that the VD program is tested.

9. BDE system
The VD baseline is ten groups of eight WIECs. Each uses one auxiliary I/O rack,
two LV racks/two PL506 supplies and eight PTC/WIEC endpoints. Totals: 10 auxiliary
racks, 20 LV racks, 20 PL506, 80 WIECs and 480 WIBs. Ten bias racks provide
separate CRP/FC protection interfaces. Drawings, parts, power calculations,
Ignition screens and test work already exist. No HD six-to-eight conversion
is counted as VD additions. The detailed panel/screen source remains in the backups.

10. BDE fan/bias example
Fan RD signals enter via DB25 and EL1004, reach the PLC over EtherCAT, and
operate the PL506 channel inhibit through EL2124. Readback should establish
the affected WIEC's final voltage/state, not merely that a command was sent.
The ISEG bias-inhibit route also exists. The dashed bias branch is conditional:
the historical HD rule links cooling and APA bias; the current VD cooling row
only assigns LV inhibition. A VD bias dependency needs explicit agreement.
The six-fan note implies 48 fan-status signals per eight-WIEC group if that
interface is used; it does not imply 48 additional inputs. Match terminals,
cables, voting, startup behavior and action time to the actual VD design.

11. PDS DAPHNE and DAQ
The main diagram adapts Figure 1 of the working SC–PDS–DPS ICD. It retains the
SC/OPC UA interface, DAPHNE ZMQ control/monitoring, DAQ CCM/opmon access and the
separate Hermes IPBus/UDP configuration route. It adds DPS/SC OPC UA and the
DPS/SNMP/LV supply power branch. The full source service figure is in backup 23;
server deployment remains outside the main talk.
Example: DPS requests a SiPM-bias inhibit through SC and the DAPHNE interface.
Verify acknowledgement and measured bias state. SC advertises the resulting
availability to DAQ, which uses it for run admission/recovery. The software
path must satisfy the required response and failure behavior; it is not yet a
qualified interlock. DAPHNE-controlled bias is distinct from cathode PoF power.
The alternate power action uses the mapped LV supply via DPS/SNMP. PDS LV scope
is 34 feeds; this does not establish one supply channel per board or module counts.

12. PDS PoF
Manuel confirms four voltage readings and one chassis temperature per box:
80 boxes give 320 voltage and 80 temperature readings, total 400. This replaces
the older 8 T + 8 V presentation case. It does not change the laser-driver count.
Compare local Opta and Beckhoff PLC implementations against those physical
signals. Monitoring reaches SC through OPC UA. The selected inhibition path
is DPS -> SNMP -> rack PDU -> mapped PoF AC outlet. A separate box-enable
signal is useful if available; it remains dashed/optional. Identify its electrical
interface, affected channels and acknowledgement before specifying hardware.
No DAQ interface or controller-per-box quantity is assigned to PoF.

13. HV
The HVS draft identifies one Heinzinger PNC HP300000, cRIO-9049 with NI-9239/9269,
ten ISEG crates and 576 bias channels (480 CRP, 96 FC). The normal drift-HV
control/readback is via LabVIEW/cRIO analog I/O. The DPS protection route uses
EtherCAT remote I/O and a wired supply interlock. Bias supplies have both SNMP
control/status and dedicated channel inhibits. Keep these roles distinct.
The example combines low-level drift-HV inhibition with the separately stated
requirement to shut down the associated FC terminations when drift HV trips.
Map supply pins, channels and feedback; allow for voltage decay. The existing
HVS/workbook disagreement over crate housing/location remains an engineering
mapping item, not a reason to discard the established hardware description.

14. CalCI thermometry
RTDs use warm cables/readout and cRIO/LabVIEW. Fibre-temperature sensors use
interrogator/readout services. Both publish through SC/OPC UA. Preserve sensor
identity, position, source time and validity when data enters a protection rule.
Thermal monitoring during cooldown/operation does not itself define a trip.
The protected load, limit, persistence and required response must be stated.
Level readout must be traced independently to its actual instrument/controller.
Do not infer RTD/FBG population or a new central DPS terminal count from the diagram.

15. CalCI lasers
The local inventory has four ionization-laser stations; the October architecture
shows the CIB OPC UA interface. The diagram links SC, DAQ/calibration requests,
DPS via SC, the station controller and its independent local safety interlocks.
Working rule O-002 denies conflicting laser/PDS operating requests and requires
emission/shutter-off evidence before PDS return. It is an operating proposal,
not an automatic PDS bias trip or a replacement for personnel laser safety.
Trace station power, permits, output feedback and trigger connections. Exact
native interfaces and installed equipment allocation still need completion.

16. CalCI purity monitors
The working hardware chain includes PrM HV/LV and front-end, xenon lamp,
digitizer and LabVIEW control/readout. SC publishes activity/status to DAQ.
Q-001 proposes allowing data acquisition with activity intervals and affected
region tagged. The older EDMS PDS ICD instead requests SiPM bias off during PrM
activity. This is a concrete requirement conflict for consortium agreement.
Do not silently treat either proposal as approved. Trace lamp control/status,
supply action and feedback; local electronics temperature and PrM RTDs are
different measurements. Actual VD models/populations are not established by
the simplified diagram.

17. Rack infrastructure
Racks, AC feeds, PDUs, smoke/humidity and sensor support are one system.
Include temperature/leak sensors where fitted. Subsystems refer to PDU outlets;
their supplies and dedicated inhibits remain in subsystem inventories. DPS
controls PDUs over SNMP, with OPC UA to SC for requests/status/logging. Local
PDU trips remain. Humidity monitoring does not create a shutdown requirement.
TDE has 20 racks with PDU-only current control. Preserve crate-status/external-
inhibit as future options. The PX3 guide is a reference prototype, not proof
that its Ignition-direct fallback already implements the selected VD PLC chain.

18. Bench tests
Use BDE vertical-slice and G271 resources for representative paths. Inject a
fault, observe actuator and final equipment state, and measure the whole delay.
Test local trips, SC/bus/power loss, reset and re-enable, and SC logs. No critical
sub-ms function has been identified so far in Manuel's review; consortia must
check that assumption. Simulation prepares cases; hardware tests qualify timing.

19. June 2027 hardware review
The system/path review produces actual additions, channel/cable allocations
and alternatives. Combine those with panel space, component power, drawings,
parts, costs, lead times and spares. Procurement follows readiness review.
Some facility interfaces may be needed in summer 2027. Full VD response-matrix
review remains early 2028. These are the proposed milestones from the email thread.
